# Mindmap Feature Documentation

## 1. Feature Summary
The Mindmap feature adds visual concept mapping to study decks in EduCards. It enables users to view hierarchical, relational concept maps representing the deck's subject matter. The backend integrates with Groq's API using `llama-3.3-70b-versatile` with JSON object mode (`response_format={"type": "json_object"}`) to produce structured mindmap graph data (`root`, `nodes`, and `edges`). If the API key is not configured or an AI generation error occurs, the system deterministically builds a fallback mindmap from the deck title and card fronts. On the frontend, a clean, zero-gradient inline SVG renderer visually presents the central root node, surrounding child concepts, and connecting lines in a modal dialog.

## 2. Changes by File

### `backend/requirements.txt`
- Added `groq>=0.9.0` to backend dependencies for Groq API integration.

### `backend/ai_service.py`
- Added `generate_mindmap(deck: Any) -> Dict[str, Any]`:
  - Extracts the deck title and card front questions from the deck object or dict.
  - Reads `GROQ_API_KEY` from `os.environ`.
  - When the key is present, calls Groq's chat completion endpoint using model `llama-3.3-70b-versatile` with `response_format={"type": "json_object"}`.
  - Sends a prompt requiring JSON output adhering to `{"root": "<topic>", "nodes": [{"id": "n1", "label": "..."}], "edges": [{"from": "n1", "to": "n2"}]}`.
  - Parses and validates that the JSON matches the expected structure.
  - If `GROQ_API_KEY` is absent, or if Groq API invocation, parsing, or validation fails, executes `_fallback_mindmap()`.
  - Never raises an unhandled exception or HTTP 500 error due to AI service failures.

### `backend/main.py`
- Imported `generate_mindmap` from `backend.ai_service`.
- Added endpoint `POST /api/decks/{deck_id}/mindmap`:
  - Retrieves the deck by `deck_id` from storage.
  - Returns HTTP 404 (`{"detail": "Deck not found"}`) if the deck does not exist.
  - Returns the mindmap JSON generated by `generate_mindmap(deck)` when found.

### `backend/test_mindmap.py` (New File)
- Added pytest unit tests:
  - `test_mindmap_missing_deck`: Validates that querying a non-existent deck ID returns HTTP 404.
  - `test_mindmap_fallback_no_key`: Validates that calling the endpoint without `GROQ_API_KEY` returns HTTP 200 with a deterministic fallback mindmap containing root, nodes, and edges based on the deck's content.
  - `test_mindmap_groq_mocked`: Validates that when Groq API is mocked, the endpoint parses and returns the AI-generated mindmap nodes and edges.
  - `test_mindmap_groq_failure_fallback`: Validates that when Groq raises an exception (e.g., rate limits or API outage), the endpoint gracefully falls back to the deterministic mock without raising HTTP 500.

### `frontend/index.html`
- In `#view-practice`: Added a "Mindmap" button in the header toolbar next to "Back to Decks".
- Added `#mindmap-modal`: A modal window containing a title and `#mindmap-container` for mounting the SVG graph.

### `frontend/app.js`
- Added `openMindmap()`: Asynchronous function that fetches `/api/decks/${currentDeck.id}/mindmap` and passes the response to `renderMindmapSvg()`.
- Added `openMindmapForDeck(deckId)`: Helper to open the mindmap modal for a given deck from the deck list.
- Added `closeMindmapModal()`: Hides the mindmap modal.
- Added `renderMindmapSvg(data)`: Renders an inline SVG element containing:
  - Center root node with deck title / topic.
  - Child concept nodes radially positioned around the root.
  - Connecting edge lines between corresponding nodes.
- Added `truncate(str, maxLen)` and `escapeXml(unsafe)`: Utility functions for text formatting and XML escaping in SVG.
- Updated `renderDecks()`: Added a "Mindmap" action button next to "Practice" on each deck card.

### `frontend/style.css`
- Added `.mindmap-root-node text` and `.mindmap-child-node text` styling rules to disable user text selection on interactive SVG labels.

### `README.md`
- Added `GROQ_API_KEY` to the Prerequisites section.
- Added `POST /api/decks/{id}/mindmap` to the API Endpoints documentation.

## 3. Environment Variables & Fallback Behavior

### Environment Variable
- `GROQ_API_KEY`: Groq Cloud API key. If provided, EduCards uses `llama-3.3-70b-versatile` to dynamically extract core themes, concepts, and relationships from the deck.

### Fallback Behavior
- If `GROQ_API_KEY` is not set, or if an invalid API key, network interruption, timeout, rate limit, or invalid JSON response occurs:
  - The application catches the exception and logs a warning.
  - A deterministic fallback mindmap is generated using the deck's title as the root node and each card's front question as a child node connected to the root.
  - The endpoint always responds with HTTP 200 and valid mindmap JSON. No HTTP 500 error is raised.

## 4. Testing

### Automated Tests
Run pytest across the test suite:
```bash
python -m pytest backend/ -v
```

### Manual Testing Procedure
1. Start the backend development server:
   ```bash
   python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --reload
   ```
2. Open your web browser at `http://127.0.0.1:8000`.
3. In the "Study Decks" tab, click "Practice" on any deck to open the practice view.
4. Click the "Mindmap" button next to "Back to Decks".
5. Verify the modal opens and displays the inline SVG mindmap diagram with the root in the center, surrounding child nodes, and connection lines.
6. Alternatively, click "Mindmap" directly on any deck card in the deck list.
7. Test with no API key (`unset GROQ_API_KEY`): Verify that the mock mindmap displays the deck's cards.
8. Test with a valid API key (`export GROQ_API_KEY="..."`): Verify that Groq generates custom dynamic mindmap nodes and edges.
